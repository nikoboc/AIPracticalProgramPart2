# 09 — ワークフロー構築のフレームワーク

`00:20:54 / 座学＋演習`

> 既存動画の説明内容を文字起こしに基づいて整理したもの。現行サービス仕様との不一致は本ドキュメントでは補正していない。

## このパートの位置づけ

講座の締めくくり。受講者が**自分のオリジナルのワークフロー**を作り始める前に、開発の基本的な流れ（フレームワーク）と注意点を学ぶ。後半は**わざとエラーが仕込まれたワークフロー**を使った、反復とトラブルシューティングの演習。

## 説明している内容

### AIワークフロー構築フレームワーク（4ステップ）

| # | ステップ | 内容 |
|---|---|---|
| 1 | **成功の定義（PRD作成）** | 何を作りたいか、どういう動きをするワークフローを作りたいか。**目的と成果物を明確化**する |
| 2 | **流用** | ゼロから全部考えて作るのではなく、**既存のリソース（テンプレート・お手本）を活用**する |
| 3 | **反復** | テスト実行とテスト改善の繰り返し |
| 4 | **トラブルシューティング** | エラーが出たとき、どこがエラーか／どのノードが動いていないかという問題を見つけ、解決する |

> この4つを順番にしっかり丁寧に回していけば、**どんな人でも必ず自動化の仕組みを完成させられる。**

### ステップ1：成功の定義（PRD作成）

- 最も重要。いわゆる**仕様書**にあたる。
- **何のために、どんな自動化を作りたいのか**を自分の中ではっきりさせること。
- 例：**毎朝のニュースを要約して Slack に通知する**
  - 必要なプロセスを頭の中で考える：ニュースサイトを見る → 記事を集める → 要約する → Slack に送る
  - 必要なツールを洗い出す：要約するための AI、Slack のノード
- こうしておくことで、**自分が今何を作っていて、どこを作っているのかが分かり、迷子にならずに進められる。**

### ステップ2：流用

- **自分でゼロから作らない。**
- 作りたいワークフローは、ほとんどの場合**すでに世界の誰かが似たようなものを作っている**。
- n8n のテンプレートには現時点で **6000以上、ほぼ7000近い**ワークフローが公開されており、日に日に増え続けている。
- まずは**使いたいツール（Slack、Google シート、Gmail など）ややりたいこと**でテンプレートを検索し、**自分が作りたいものと似たワークフローを探す**。
- YouTube やネット上で公開されているチュートリアルを調べて活用するのもかなり良い方法。

### ステップ3：反復

テストと改善を繰り返すプロセス。**非常に重要なポイント：**

> **一つ修正を加えたら、一度テストを実行する。**

- 例えば10箇所が赤くなっている状態で、10箇所全部を自分流に修正してから最後にテスト実行すると、またエラーが出たときに**10箇所のうちどこが原因だったのか分からなくなる**。
- **1つノードを追加したら1つ実行**。1つ1つ丁寧に追加していくことが、**結果的に一番の最速**でワークフローを完成させる方法。
- 一気に作って一気に実行し、エラーが出てもどこか分からない、という状態にならないよう注意する。

### ステップ4：トラブルシューティング

- 反復の最中に**必ずと言っていいほどエラーに出会う**（赤くなってエラーコードが出る）。
- エラーが起きたときに**原因を理解して解決策を実行する**プロセス。
- **開発経験が少ない人にとって、AI時代における「AIを使った反復とトラブルシューティング」の方法を学ぶことは、何よりも重要なスキル。**

## 演習：わざとエラーが出るワークフローの修正

### 演習用ワークフローの読み込み

1. 講師が指定する URL にアクセスし、**ワークフローのファイル（JSON）をダウンロード**する。
2. n8n の画面右上のボタンから **「Import from File」** を押し、ダウンロードしたファイルを開く。
3. → ワークフローが表示される。
   - 構成：**RSS トリガー**で指定されたサイト（例：Yahoo!ニュース）から情報を抽出し、**Edit（エディット）ノード**につながっている、ごくシンプルなワークフロー。

### 1回目のテスト実行

1. **テスト実行**する。
2. → **エラーが出る**（成功せず失敗している表示）。**これで一応「成功」**（演習としては想定どおり）。

### トラブルシューティング（AIに聞く）

Google AI Studio の Gemini、ChatGPT など、手持ちの文章生成AIを開く。**AIに投げるプロンプトには以下の3点を必ず含める：**

| # | 含めるもの | 取り方 |
|---|---|---|
| 1 | **エラーメッセージ** | 画面下部のアウトプットのエラー部分を押すと、詳しいエラーが出る。右上からコピーできる |
| 2 | **ワークフローの概要（JSONファイル）** | ワークフローをコード化した JSON ファイルを添付する（Import に使ったファイルをそのまま添付） |
| 3 | **依頼文** | 「このエラーを解決したいです。何がエラーになっていて、どのように解決すればいいか教えてください」 |

### 修正の適用

- ChatGPT が原因を洗い出してくれた。
  - **原因：ノードの値に入っている「式」の文法ミス。**
  - 「あなたのワークフローを見ると、ここの値が次のようになっていて、正しい書き方はこうです」と提示され、下に**修正手順**が分かりやすく書かれている。
- 修正手順どおりに作業：
  1. n8n でエラーが出ているノードを開く。
  2. **Value の右の `fx` をオン**にする。
  3. 値を、AI が示した**正しい式に差し替える**（ペースト）。
- 修正したら**再度実行**。
- → **ワークフローは「成功」の表示になる。**

### しかし成功していない（重要な学び）

- 実行は成功と表示されたが、**アウトプットには何も表示されていない。**
- このワークフローは**ニュースサイトからタイトルを引っ張ってきて表示させる**ものなのに、結果が得られていない。
- **ステップ1「成功の定義」**に立ち返ると、このワークフローの成功の定義は**「抽出したニュースサイトのタイトルを抽出する」**。
- **ワークフロー自体が成功していても、自分が欲しい結果が得られていなければ、それは失敗。**
- そのため、**ステップ3（反復）とステップ4（トラブルシューティング）を繰り返す必要がある。**

### 2回目以降の反復

1. 画面のスクリーンショットを撮る、またはワークフローを再度ダウンロードして JSON にする。
2. 「ワークフロー自体は成功したけれどもタイトルが表示されません。どのように改善したらいいですか」と送る。
3. **自分の求めている結果が出るまで、ChatGPT や Gemini と壁打ちして解決していく。**
4. 最終的に、抽出したニュースサイトのタイトルがアウトプットに表示されれば**演習完了**。

## 演習からの学び（締めのメッセージ）

- AIとの対話において、**こちらの意図・目的を明確に伝えるプロンプトがいかに重要か**を体感してほしい。
- エラーが起きたとき、AIの回答は素晴らしいヒントになる。しかし同時に、**n8n の基本的なデータの流れを自分でも理解していくことが、トラブルシューティングを簡単にする重要な鍵**になる。
  - **前のノードから次のノードへデータが正しく渡されているか**
  - あるノードの**アウトプット**と、次のノードの**インプット**、そして**アウトプット**
  - **どのノードまで正しく動いているか**を確認する癖をつける。
- 今後は AI を使って、さらに一歩進んで **n8n で使える簡単なコード（JavaScript など）**にも取り組める。
- この講座では、**ノーコードプラットフォームにおけるデータフローの構造**を学んできた。
  - データが RSS フィードから取り込まれ、ノードで処理され、結果が出力される。
  - **コードの知識がなくても、こうした論理的な思考でワークフローを構築できる点が n8n の画期的な部分。**
- AI を活用しながらエラー対処と改善を反復することで、**論理構造への理解は思うよりずっと早く深まる。**
- **AI はあくまでヒントや選択肢を提供してくれる優秀なアシスタント。** AI が出した選択肢やヒントを**どう採用し、どう修正するのか、その最終的な判断は必ずあなた自身（人間）が行う必要がある。**
- この感覚を忘れずに、オリジナルのワークフロー構築にチャレンジしてほしい。
