## 講座全体のストーリー

「**なんちゃって ChatGPT**」を1本のワークフローとして作り始め、段階的に機能を足していく構成になっている。各回は**欠点を体験させてから、それを解消する機能を追加する**流れで統一されている。

```
③ トリガー + AI Agent          → 頭脳がなくエラー
④ + Chat Model（OpenRouter）   → 会話できるが記憶がない
⑤ + Memory                     → 記憶できる
  + System Message             → 役割・口調を制御できる
⑥ + Wikipedia ツール           → 外部情報を取れる
  + Gmail ツール               → 複数ツールの順番制御が課題に
⑦ + HTTP Request（Tavily）     → 専用ノードがないサービスとも連携できる
⑧ サブエージェントへ分離        → 別キャンバス化して管理性・安定性を上げる
⑨ フレームワークと演習          → 自力でオリジナルを作れる状態へ
```

## 講座を通して繰り返し強調されている点

- **n8n に自動保存はない。変更したら都度 Save。**（②以降ほぼ毎回）
- **システムメッセージが AIエージェント開発の最重要機能。** ツールが増えるほど、その使い方の制御に不可欠になる。（⑤⑥⑧）
- **API キーは他人に教えない。** クレジットカード情報と同等の機密性。（④⑦）
- **エラーが出たら、まず AI（ChatGPT / Google AI Studio）に聞く。** エラーメッセージ＋ワークフローの JSON ＋依頼文の3点セットで渡す。（⑦⑨）
- **1つ修正したら1つテスト。** まとめて直すと原因が特定できない。（⑨）
- **最終的な判断は人間が行う。**（⑨）
