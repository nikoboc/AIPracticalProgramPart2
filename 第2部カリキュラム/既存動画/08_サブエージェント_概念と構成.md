# 08 — サブエージェント 概念と構成

`00:21:23 / 座学＋画面操作`

> 既存動画の説明内容を文字起こしに基づいて整理したもの。現行サービス仕様との不一致は本ドキュメントでは補正していない。

## このパートの位置づけ

AIエージェントのパフォーマンスを最大化するための強力なテクニック、**サブエージェント**を学ぶ。⑦で作った Tavily の HTTP Request を**別キャンバスのリサーチ担当サブエージェントに移植**し、メインエージェントから呼び出す構成を作る。

## 説明している内容

### サブエージェントとは

- **メインエージェントの下に、それぞれの専門分野を担当するサブエージェントを配置する**という考え方。
- 例え：会社で優秀なマネージャーの下に、リサーチ担当の部下、メール作成担当の部下、データ分析担当の部下が配置されるイメージ。**AI同士のチームを組む／専門家を一人ずつ作る**感覚。

### なぜサブエージェントが必要か

一つのメインエージェントに「あれもこれも」と指示を詰め込むと：

- AIエージェント自体が**混乱しやすい**
- **出力が安定しない**／エラーばかり出る可能性が高くなる
- 安定した出力結果を目指すと**より複雑なシステムメッセージ**が必要になり、**コストがかさむ**

### サブエージェントの構成方法は2つ

| 方法 | 内容 |
|---|---|
| ① 同一キャンバス | メインエージェントと同じワークフロー内にサブエージェントも全部追加する |
| ② **別キャンバス（本講座の推奨）** | メインエージェントとは**全く別のワークフロー／キャンバス**にサブエージェントをそれぞれ作り、接続する |

> **本講座は ② 別キャンバスをベストプラクティスとして推奨する。**

### 別キャンバスにするメリット

- エージェントごとにキャンバスを完全に分けることで、**機能の追加・修正がそれぞれしやすくなる**。
- **どこで問題が起きたかを特定しやすい**＝**エラーハンドリングがしやすい**。
- 1つのワークフローに何もかもつなげると、どこでエラーが起きていてどこを修正すればいいかが分かりにくくなる。別キャンバスなら「このキャンバスのこのノードでエラーが起きている」と分かりやすい。

## 画面操作の手順

### 1. サブエージェント用のワークフローを新規作成

1. メインの `デモ` キャンバスはそのままにして、**ダッシュボードに戻る**。
2. 右上の**「Create Workflow」**を押して新規キャンバスを開く。
3. 名前を付ける（動画では **リサーチ担当のサブエージェント**という趣旨の名前。以降「サブエージェントサーチ」と呼称）。

### 2. トリガーの設定（他ワークフローから呼び出される側）

- サブエージェントは、メインエージェント（マネージャー）から**呼び出されて動く部下**の動きをする必要がある。

1. キャンバスを開いて検索し、**サブワークフローを動き出すためのトリガー**（他のワークフローから実行・呼び出されたときにこのワークフローを動かし始めるトリガー）を追加する。
2. トリガーノードの設定画面で、**Data Mode を `All Data` にする**。
   - こうすることで、**メインエージェントから渡された指示・データをすべて受け取れる**ようになる。

### 3. AI Agent と Chat Model を追加

1. トリガーの**＋**から **AI Agent** を追加（メインと同じ）。
2. Chat Model も同じく **OpenRouter** を追加。
3. Credential の下の部分を見ると、**④で設定した認証情報がそのまま選択できる**。
   - → **一度 Credential を登録すれば、全く別のワークフローでも簡単に引き継げる**という便利な機能。

### 4. Tavily の HTTP Request をメインから移植する

1. 一旦 **Save**。
2. メインの `デモ` キャンバスに戻り、**Tavily の HTTP Request ノードをコピー**（クリップボードにコピーされる）。
3. ダッシュボード経由でサブエージェントのキャンバスに戻り、**Ctrl+V / Cmd+V** で貼り付け。
4. 貼り付けた HTTP Request ノードを、**サブエージェントの AI Agent の右側「Tool」に接続**する。

→ これで **HTTP Request（Tavily）という検索ツールだけを持った、検索特化型のAIエージェント**が完成。

### 5. テスト用データをピン止めする

サブエージェントのトリガーは「他のワークフローから呼び出されることで起動」するため、**このワークフロー単体で実行を押しても、呼び出す親（マネージャー）がいないのでテスト実行ができない。**

1. トリガーノードを開くと、画面右側に **Output** の欄が出る。
2. 右上の**鉛筆マーク**を押すとコードを書く場所が出る。
3. 動画では **`1` という数字をアウトプットする**設定を書く。
4. 右上の **Save** を押し、**ピン止めされているか確認**（**オレンジ色**になっていればピン止めされている）。

→ テスト実行時は**常に `1` というデータが流れてくる**状態になる。

### 6. AI Agent のプロンプト設定

1. AI Agent ノードを開くと、左側の Input に **`query: 1`** と、設定した `1` が表示されている。
2. **Source for Prompt (User Message)** を、下の選択肢（手動で入力欄を指定する方）に切り替える。
3. 入力欄に **`query`** を引っ張ってきて載せる → `1` という数字が入力される。
4. AI Agent を実行すると、**`1` がアウトプットされる**。エラーが出ず**緑色**になっていれば正解。

### 7. サブエージェントのシステムメッセージ

**Add Option → System Message** から、役割を明示する。動画で設定した内容：

> あなたは優秀なリサーチャーです。ユーザーから受け取ったメッセージの内容を、あなたが持っている HTTP リクエストのツールを使ってリサーチをして、その結果だけを回答してください。

→ **サブエージェントの役割はしっかりと明確に指示する。** 設定できたら **Save**。

### 8. メインエージェントと接続する

1. メインエージェントのワークフローに戻る。
2. サブエージェントに移植した **HTTP Request ノードをメインの AI Agent から削除**する（消して大丈夫）。
3. メインの AI Agent ノードに新しいツールを追加：**`Call n8n Workflow Tool`** をクリック。
4. AI Agent に接続されたことを確認し、そのノードを開く。
5. **先ほど作成したサブエージェントのワークフローを選択**（自分が作ったワークフロー一覧から「サブエージェントサーチ」を選ぶ）。

→ これでこのツールは**「サブエージェントサーチという部下を呼び出すツール」**になった。チャットで送ると、その文章を理解してサブエージェントに送り、サブエージェントが起動する。

### 9. メインエージェントのシステムメッセージを修正

新しく入った部下（サブエージェントツール）のことを教える。動画で設定した内容：

> あなたに「サブエージェントサーチ」というリサーチが得意な部下がいます。ユーザーから何かしら調べてほしいと依頼された場合、必ずこのサブエージェントサーチツールを使ってリサーチを実行してください。

→ **Save** を押してメインエージェント完成。

### 10. サブエージェント側の修正（ピンを外す）

- サブエージェントのトリガーに設定した **`1` というテスト用データのピンを外す**。
- **Save** して保存。

### 11. 動作確認

1. メインエージェントのチャット欄に **`織田信長について調べて教えてください`** と送信。
2. → 「織田信長は日本の戦国時代の〜」という回答が返ってくる。

**動作の流れ**：メインエージェント自体にはリサーチ用ノードがないが、`Call n8n Workflow Tool`（サブエージェントサーチ）が別のサブエージェントを呼び出す → サブエージェント側でリサーチ → 結果をメインが受け取る → メインの Chat Model が判断して出力する。

## 動画中の入力例・設定値

| 項目 | 動画での値 |

| サブエージェントのツール | HTTP Request（Tavily／メインからコピー） |
| テスト用ピン止めデータ | `1` |

## 講師が強調している点

- **最初から別キャンバスにサブエージェントを作るのがベストプラクティス。**
- Credential は**一度登録すれば別ワークフローでも引き継げる**。
- サブエージェント単体ではテスト実行できないため、**ピン止めしたテストデータ**を使う。テストが終わったら**ピンを外す**。
- 既に同一キャンバスに作ってしまっていても心配不要。**ノード群をコピーして別ワークフローに引っ越せば**、メインから呼び出せる。
- メインとサブを明確に区分けすることで、**管理しやすく強力なAIエージェントの仕組み**が作れる。
