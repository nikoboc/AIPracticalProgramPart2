## 講座の位置づけ

第1部は「AIに何をどう依頼し、出力をどう検証するか」を扱い、L5入口までを到達点とした。
第2部はその続きとして、**依頼を1回ずつ人が出す状態から、依頼の手順そのものを仕組みとして外に置く状態へ移す**。
道具は n8n（ノーコードのワークフロー自動化プラットフォーム）。最終回では、作った仕組みを**n8n の公開テンプレートとして世に出す**ところまで進む。

| | 第1部 | 第2部 |
|---|---|---|
| 主語 | 人がAIに依頼する | 仕組みがAIを呼び出す |
| 成果物 | 依頼設計・検証記録・個人プロジェクト | 動くワークフロー・公開テンプレート |
| 評価 | 説明できるか | **動くか、他人が再現できるか** |

## 到達段階（第2部の独自指標）

第1部の L1〜L5 とは別軸。n8n の習熟度として N1〜N3 を置く。

| 段階 | 定義 |
|---|---|
| **N1** | 講師の指示のもとで n8n の画面を操作し、1本のワークフローを動かせる |
| **N2** | 目的から逆算して、自分でノードを選び・つなぎ・エラーを直せる |
| **N3** | 他人が再現できる形に整え、公開・共有できる |

### 環境と費用

| 項目 | 内容 | 注意 |
|---|---|---|
| n8n Cloud | 無料トライアル **14日間**（Pro 相当、実行1,000回まで、クレカ不要） | **後述の日程の注意を必ず読むこと** |
| LLM | ① n8n の **Gateway credits**（初期残高 $2.00、プロバイダ登録不要）／② **OpenRouter**（デポジット制、少額でよい） | 第2章で選択。②を選ぶ場合は**APIキーに必ず利用上限を設定させる** |
| Tavily | 無料枠 毎月1,000クレジット、クレカ不要 | 第3章で使用 |
| Google アカウント | Gmail ツールの認証に使用 | 業務アカウントを使わせない。演習用を用意させる |
| 受講者のPC | ブラウザのみ。インストール不要 | — |

### 日程の設計上の注意（重要）

**n8n Cloud の無料トライアルは14日間。全6回を週1回で実施すると、第3回あたりでトライアルが切れる。**
次のいずれかを、**第1回の前に**決めておく。

1. **第1〜3回を14日以内に詰める**（週2回など）。第4回以降は有料プラン（Starter）へ移行する前提で案内する。
2. **最初から有料プラン（Starter）を契約**して6回を通す。
3. 第1〜3回をトライアルで実施し、**第4回の前に新規インスタンスへ移し替える**（ワークフローはエクスポート／インポートで移送できるが、Credential は移送されず再登録が必要）。

**3は受講者の負担が大きいため、原則1または2を推奨する。**

### AIエージェント（Claude Code 等）の扱い

**本カリキュラムは、受講者が有料のAIエージェントを契約していないことを前提に設計する。**
n8n の MCP サーバー経由でワークフローをAIに生成させる方法は、**標準カリキュラムには含めない**。
理由は、受講者が自分でノードを選んで組めるようになることが第2部の到達点であり、生成された結果を検証できない段階で生成から入ると、この到達点が崩れるため。

ただし、**受講者がすでに契約しており、かつ説明を希望する場合には対応できる必要がある**。
その場合は [付録A](#付録a--aiエージェントから-n8n-を操作するオプション) をオプションとして扱う。**標準の到達判定には一切含めない。**

## CHAPTER 01 — n8n に触れる：画面・ドラフト・公開

`SETUP / N1`

**対応する既存動画**：① オリエンテーション／② 基本操作／③ AIオートメーションとAIエージェント
**参照**：[`最新仕様反映/01_オリエンテーション.md`](最新仕様反映/01_オリエンテーション.md)・[`02_基本操作.md`](最新仕様反映/02_基本操作.md)・[`03_AIオートメーションとAIエージェント.md`](最新仕様反映/03_AIオートメーションとAIエージェント.md)

### 起点の問い

> AIに毎回自分で依頼するのと、依頼の手順を仕組みとして置いておくのは、何が違うのか？

### 到達点

自分のインスタンスを作り、キャンバスにトリガーとノードを置いて実行し、**編集はドラフトとして自動保存され、本番反映は Publish である**という2段構えを説明できる。

### 扱う内容

- n8n は、2,000種類以上のサービスをノードとしてつなぎ、処理の流れを図として組み立てるプラットフォーム。コードを書かずに構築できる。
- ワークフローは大きく2種類。**決められた手順を毎回そのとおり実行するAIオートメーション**と、**状況に応じてAI自身が手順を選ぶAIエージェント**。本講座は後者を作りながら、前者の考え方も扱う。
- すべてのワークフローは**トリガー**から始まる。手動実行、チャット、スケジュール、Webhook など。
- **n8n Cloud はアカウントとインスタンスが実質1対1**。ワークフロー・Credential・実行履歴・残高はすべてインスタンス単位に属する。サインアップがそのままインスタンス作成になる。
- **保存の概念が他サービスと違う。** 編集内容は1〜5秒で自動保存されるが、それは**すべてドラフト**であり、本番には影響しない。本番で動くのは **Publish したバージョン**だけ。
- サイドバーにあるのは Overview / Templates / Insights。Workflows・Credentials・Executions・Data tables は **Overview ページの中**にある。

### 標準セッション設計

| ブロック | 目安 | 内容 |
|---|---|---|
| 接続と現在地 | 10分 | 第1部の成果を確認し、第2部で何がどう変わるかを共有 |
| アカウント作成 | 15分 | n8n Cloud のトライアル登録。インスタンス＝アカウントという構造を先に説明 |
| 画面の地図 | 15分 | Overview／キャンバス／サイドバーの役割。どこに何があるか |
| ドラフトと公開 | 15分 | 自動保存・Publish・Unpublish・バージョン履歴を実際に触る |
| 最初のワークフロー | 20分 | Chat Trigger + AI Agent を置いて実行し、**エラーを出す** |
| 振り返りと宿題 | 10分 | エラーの意味を言語化。次回の事前準備を指示 |

そのうえで、**なぜ動かないのかを、AI Agent の画面に出ている表示を根拠に自分の言葉で説明する**。

### 宿題

## CHAPTER 02 — 動くエージェントを作る：認証・記憶・役割・ツール

`BUILD / N1→N2`

**対応する既存動画**：④ Credential（認証情報）／⑤ メモリとシステムメッセージ／⑥ ツールとオーケストレーション
**参照**：[`最新仕様反映/04_Credential認証情報.md`](最新仕様反映/04_Credential認証情報.md)・[`05_メモリとシステムメッセージ.md`](最新仕様反映/05_メモリとシステムメッセージ.md)・[`06_ツールとオーケストレーション.md`](最新仕様反映/06_ツールとオーケストレーション.md)

### 起点の問い

> 会話できるだけのエージェントに何が足りず、それぞれをどの部品が埋めるのか？

### 到達点

Chat Model・Memory・System Message・ツールを1つずつ追加し、**追加前に何ができなくて、追加後に何ができるようになったか**を各段階で説明できる。

### 扱う内容

- **Credential（認証情報）は、外部サービスへのログイン情報を n8n に預けて名前を付けたもの。** 一度作れば同じインスタンス内の他のワークフローから使い回せる。ワークフローをJSONで書き出しても、Credential の中身は含まれない。
- LLM の接続には2ルートある。**① Gateway credits**（プロバイダの登録もAPIキーも不要。初期残高 $2.00）、**② 外部プロバイダ**（OpenRouter など。APIキーを自分で発行する）。講座では**②を本筋**とし、①は「試すだけならこれで足りる」と紹介する。
- OpenRouter を使う理由は、**1つのAPIキーで多数のモデルを差し替えられる**こと。モデル比較が講座の目的に合う。デポジット制で、入金した分だけ使える。
- **APIキーには必ず利用上限（Credit limit）を設定させる。** OpenRouter 公式も全キーへの上限設定を推奨している。
- **Memory がないと、エージェントは直前の発言も覚えていない。** Simple Memory を足すと、指定した往復数ぶんの会話を保持する。
- **System Message は、エージェントの役割・口調・禁止事項を固定する指示。** ユーザーの入力とは別枠で、毎回必ず適用される。
- **ツールは、エージェントが必要と判断したときに自分で呼び出す外部機能。** Wikipedia のような情報取得、Gmail のような外部操作がある。
- ツールが増えると、**どれをいつ、どの順で使うかという制御（オーケストレーション）が課題になる。** System Message で順序を指示する、ツール実行前に人間の承認を挟む（Human-in-the-loop）といった手段がある。

### 標準セッション設計

| ブロック | 目安 | 内容 |
|---|---|---|
| 宿題レビューと準備確認 | 10分 | テンプレート観察の共有。LLM の準備状況を確認 |
| 認証情報と2つのルート | 10分 | Credential の考え方。Gateway credits と外部プロバイダの違い・費用感 |
| Chat Model を接続する | 15分 | APIキー発行（**上限設定を必ず実施**）→ Credential 登録 → 会話成立 |
| 記憶がない問題 → Memory | 10分 | 名前を名乗って聞き返す実演 → Memory 追加 → 再実行 |
| 役割を固定する → System Message | 15分 | 口調・役割・禁止事項を指示。変更前後を比較 |
| ツールを足す（Wikipedia） | 10分 | AIが自分でツールを呼ぶ様子をログで確認 |
| ツールを足す（Gmail） | 15分 | Google 認証 → 下書き作成。**送信ではなく下書きで止める** |
| 課題の提示と宿題 | 5分 | 順番どおりに動かない例を見せ、次回へつなぐ |

`PRACTICE`

### 成果物

- 会話・記憶・役割・ツールを備えたエージェント1本（ドラフト）

初見の状態で次を実演・説明できること。必須項目すべて到達。

1. Credential を**新規に1件登録できる**（手順を口頭で説明しながら操作できる）。

3. System Message とユーザー入力の違いを説明できる。
4. **APIキーに上限を設定した理由を説明できる。**

### 宿題

## CHAPTER 03 — 広げる・分ける・直す：API・サブエージェント・フレームワーク

`EXTEND / GATE 1 / N2`

**対応する既存動画**：⑦ APIとHTTPリクエスト／⑧ サブエージェント／⑨ ワークフロー構築のフレームワーク
**参照**：[`最新仕様反映/07_APIとHTTPリクエスト.md`](最新仕様反映/07_APIとHTTPリクエスト.md)・[`08_サブエージェント_概念と構成.md`](最新仕様反映/08_サブエージェント_概念と構成.md)・[`09_ワークフロー構築のフレームワーク.md`](最新仕様反映/09_ワークフロー構築のフレームワーク.md)

### 起点の問い

> 専用ノードが無いサービスは諦めるのか。1本のワークフローが大きくなりすぎたらどうするのか。壊れたとき、何から見るのか。

### 到達点

HTTP Request で任意のサービスと連携し、処理をサブエージェントへ分離し、**エラーの原因を切り分けて自力で直す手順**を持つ。

### 扱う内容

- **専用ノードは「よく使われるサービス」にしか用意されない。** 用意されていないサービスは、APIを直接叩く。
- **API はサービスが外部に開けている窓口**で、決められた形式で要求を送ると結果が返る。**HTTP Request ノード**がその窓口を叩く汎用ノード。
- **cURL は API 呼び出しをテキスト1行で表したもの。** 多くのサービスが公式ドキュメントに載せている。**n8n はこれを貼り付けるだけでノードに変換できる**ため、実質的にAPI連携の大半はコピーと貼り付けで済む。
- **APIキーは Credential に登録する。ノードのヘッダーに直書きしない。** 直書きすると、ワークフローのJSONを外部に渡した瞬間にキーが漏れる。Credential に入れた値は JSON に含まれない。
- 1本のキャンバスに全部を詰め込むと、**見通しが悪くなり、AIが選ぶツールも増えすぎて安定しなくなる。** 役割ごとに切り出したものが**サブエージェント**。
- 構成方法は3つ。**別ワークフロー化**（管理性が高い。本番では呼び出される側の **Publish が必須**）、**同一キャンバスの AI Agent Tool**（手軽）、**Agent Builder**（発展）。
- **ワークフロー構築のフレームワーク（4ステップ）**：① 成功の定義（PRD）→ ② 流用（テンプレート・既存ワークフロー）→ ③ 反復 → ④ トラブルシューティング。
- トラブルシューティングは**まず n8n の中で**。実行履歴で**どのノードで止まったか**を特定し、そのノードの入力と出力を見る。それでも解けないときに外部のAIへ相談する。
- **外部のAIにワークフローのJSONを渡す前に、中身を必ず確認する。** APIキー・メールアドレス・社内URLが残っていないかを見て、必要ならダミーに置き換える。

## CHAPTER 06 — n8n 公認クリエイターになる

`PUBLISH / GATE 3 / N3`

**調査日**：2026-09-22（出典は本章末尾）

### 起点の問い

> 自分が作ったものを、見知らぬ誰かが設定して動かせる形にするには、何が足りないか？

### 到達点

n8n のテンプレート公開の要件を理解し、自作ワークフローを要件に適合させ、**Creator Portal から投稿できる状態**にする（投稿自体をセッション内で行うかは受講者の判断でよい）。

### 扱う内容

#### 制度の全体像

- 投稿は **Creator Portal**（`creators.n8n.io`）から行う。アカウント登録が必要。
- 流れは **ワークフロー作成 → JSONで書き出し → 説明文を書く → Creator Dashboard から投稿 → レビュー → 公開**。
- **未認証のクリエイターは、一度に1件しか投稿できない。** 承認されるまで次を出せない。
- **承認されたテンプレートが3件に達すると Verified Creator（認証クリエイター）**になり、以下が得られる。
  - 最大4件までのまとめて投稿
  - **認証クリエイターバッジ**（サイト上に表示される）
  - 製品チームと直接つながる**専用 Discord チャンネル**
  - **有料テンプレートの販売**が可能になる

#### テンプレートの要件（満たさないと公開されない）

**ワークフロー側**

- **sticky note の使用は必須。**
  - **メインの sticky（必須・1枚だけ）**：黄色、キャンバスの左上、100〜300語。`### How it works` と `### Setup` を含める。`### Customization tips` は任意。
  - **セクション sticky（4ノード以上のワークフローでは必須）**：白（ダークモードでは灰）、50語未満、見出し＋1〜2行。**複数ノードをまとめて覆う**ように伸ばす。
  - **警告 sticky（任意）**：赤、1ノードのみを覆う。使いすぎない。
  - **動画 sticky（任意・推奨）**：sticky に `@[youtube](動画ID)` と書くと埋め込まれる。
- **全ノードを、役割が分かる名前にリネームする。**
- **HTTP ノードにAPIキーを直書きしない。**
- **個人を特定できる値を消す**（Google Sheets のID、Telegram のチャンネル、実在のメールアドレスなど）。
- 利用者が設定すべき値は、**Set Fields ノードにまとめる**。
- 利用者が n8n の初心者である前提で作る。設定の手間を最小にする。

**説明文側**

- **英語で書く。** 文法的に正しい明快な英語。**AIで校正してよい**（ガイドライン自身がそう書いている）。
- **Markdown を使う。HTMLタグは不可。**
- **約200語**を目安にする。
- **タイトルは「動詞＋対象＋to/on/in/from どこ」の形式**。文頭のみ大文字。**絵文字や誇張は禁止**（守らないと n8n 側で変更される）。
- 推奨セクション：**Who's it for / How it works / How to set up / Requirements / How to customize**。
- コミュニティノードを使っている場合は、**セルフホスト限定である旨の注記**と、**ワークフロー画像**を先頭に置く。

**禁止事項**

- **他人のワークフローの転載・盗用（アカウント凍結の対象）。**
- 低品質・作り込み不足のテンプレート（公開されない）。
- ガイドラインを読まずに出すこと（差し戻しが増えるだけ）。

### 標準セッション設計

| ブロック | 目安 | 内容 |
|---|---|---|
| 制度の説明 | 15分 | 投稿から認証クリエイターまでの道筋。1件ずつ→3件承認→バッジ・Discord・有料販売 |
| 良い例を読む | 10分 | 公開済みテンプレートを2〜3本ひらき、sticky と説明文の書き方を観察 |
| テンプレート化 | 20分 | 個人情報・認証情報の除去、ノード名の整備、設定値の Set Fields への集約 |
