## このパートの位置づけ

③で作った「骨組みだけで頭脳がない」AIエージェントに、LLM を接続して**考える力（頭脳）**を与える。そのために必要な **Credential（認証情報）** の概念を扱う。

**動画版からの構成変更**：現行の n8n には「API キーを用意しなくても LLM を動かせる」ルート（Gateway credits）が増えたため、**ルートAで先に「動く」体験をさせてから、ルートBで Credential の仕組みを学ぶ**構成を推奨する。Credential の概念自体は⑥の Gmail 連携や⑦の外部 API で必ず必要になるので、省略はしない。

## 説明している内容

### Credential（認証情報）とは

- n8n 自身が、Gmail・Slack・LLM（AI）などとつなげるために必要な**パスワード／認証情報**のこと。
- n8n の中で**暗号化して保存**され、一度登録すれば**別のワークフローからも選ぶだけで使い回せる**（⑧で実際に体験する）。

### 【全面追記】LLM を接続する2つのルート

| | ルートA：Gateway credits | ルートB：自分の API キー |
|---|---|---|
| 準備 | **なし。**ノードの認証情報欄で選ぶだけ | プロバイダのアカウント作成 → API キー発行 → n8n に Credential 登録 |
| 課金 | n8n の残高から一括で引かれる（前払い） | プロバイダごとに個別課金 |
| 使えるモデル | n8n が対応しているモデル・サービスのみ | n8n が連携しているすべて |
| 利用条件 | **n8n Cloud の Starter / Pro プラン**（Enterprise・セルフホストは対象外）。n8n 2.36 以降。**無料トライアル中のアカウントでも利用できる** | 制限なし |

#### ルートA：Gateway credits（現行の最短ルート）

1. ノードの設定を開く。
2. 認証情報の欄で **「Use Gateway credits」** を選ぶ（残高が表示される）。
3. あとは普通にノードを設定して実行する。

- ノードパネルの上部に **「Included in n8n」** セクションがあり、Gateway credits で動かせる AI モデル／ツールがまとまっている。検索結果にもクレジットのタグが付く。
- タグの表示は、チャージ前は **「Free credits」**、チャージ後は **「Gateway credits」**。
- 残高が 0 になると、そのノードは失敗する。インスタンスのオーナーがチャージ（手動 or 自動）できる。
- ノード単位で「Use my own credential」に切り替えられるので、**1つのワークフローの中で Gateway credits と自前キーを混在させられる。**

> 【2026-09-22 実機確認】**無料トライアルのアカウントでも Gateway credits は使え、初期残高は $2.00 のフリークレジット**だった。受講者は**API キーを一切用意せずに④を通過できる**。
> ただし**残高の額は n8n 側の運用で変わりうる**ので、収録・実施の当日に実画面で額を確認すること。

#### ルートB：自分の API キー（本講座のメインルート）

外部サービス連携（⑥ Gmail、⑦ Tavily）では結局 Credential が必要になるため、**ここで仕組みを理解しておく**。動画と同じく OpenRouter を教材に使う。

### なぜ OpenRouter を使うのか

- ChatGPT・Claude・Gemini など様々な LLM があるが、**一つの認証情報で手軽に複数のモデルを利用できる**のが OpenRouter。
- ChatGPT や Gemini を直接使う場合も**設定方法は同様**なので、参考になる。

### コストの考え方

- LLM（AIの頭脳）を使うには**コストがかかる**。イメージは**電気代**。自動化ワークフローを動かすための電気代のようなもの。
- 一般的には**1回の実行で1円かかるかかからないか**程度だが、**ゼロではない**点に注意。
- 金額は**トークン**という単位で計算する。
  - 【補足・修正】「1文字＝1トークン」は**英語ならおおむね妥当**だが、**日本語は1文字あたり 1〜2 トークン程度**になることが多い。日本語で長文をやり取りすると、体感より早くトークンを消費する。
- 対話が多い・実行が多い・処理が多いほど料金がかかる、というシンプルな仕組み。
- 【追記】⑤で扱う **Context Window** の値を大きくすると、毎回の送信トークン数がそのぶん増える。コストに直結する設定なので、⑤と紐づけて説明する。

### OpenRouter はデポジット制

- Suica や PASMO と同様、**あらかじめ OpenRouter 側にクレジットをチャージ**しておき、使用するごとに減っていく方式。
- そのまま OpenRouter を使う場合はクレジットのチャージが必要。

## 画面操作の手順

### 1. OpenRouter で API キーを発行する

1. OpenRouter のサイト（openrouter.ai）を開く。
2. **「Sign up」**からアカウントを作成（Google アカウント、またはメールアドレス＋パスワード）。
3. ログイン後、**Keys**（https://openrouter.ai/keys ）のページを開く。
4. **API キーを新規作成**する。
5. 設定項目
   - **Name**：発行する API キーの名前。例 `n8nデモ`。
   - **Credit limit（上限）**：どれくらい API を使用してよいかの上限。
     > ⚠️ **【重要な修正】動画では「設定せずに進行」しているが、現行の OpenRouter 公式ドキュメントは「すべてのキーに上限を設定すること」を強く推奨している。** 上限なしのキーが漏れると、**オートチャージ分も含めて残高全額**を使われる可能性がある。講座では**少額（例：$5）の上限を必ず設定させる**こと。日次・週次・月次の上限も設定でき、リセットされる。
6. 作成すると新しいキーが表示される。
7. コピーボタンでコピーし、**パスワードマネージャーなど安全な場所に保管**する。**一度閉じると再表示できない。**

> ⚠️ **API キーの取り扱い**：連携に必要なパスワードのようなもの。**他の人に絶対に教えないこと。** クレジットカード情報と同等の機密性がある。
>
> 【追記・⑦⑨との関連】**API キーをノードのパラメータ欄に直接書くと、ワークフローの JSON をエクスポートしたときにキーもそのまま出力される。** ⑦・⑨では「エラー解決のためにワークフローの JSON を ChatGPT にアップロードする」手順が出てくるため、**キーは必ず Credential に登録し、パラメータ欄に直書きしない**（⑦で詳述）。Credential に登録した値は JSON エクスポートには含まれない。

### 2. n8n 側で Chat Model を接続する

1. n8n のキャンバス画面に戻る。
2. **AI Agent ノードの下にぶら下がっている「Chat Model」の＋ボタン**をクリック。
3. 接続できる Chat Model の一覧が表示される。
   - **ルートAで進める場合**：一覧上部の **「Included in n8n」** から対応モデルを選び、認証情報欄で **Use Gateway credits** を選択。→ 手順4〜6は不要。
   - **ルートBで進める場合**：**`OpenRouter Chat Model`** を選択。
4. 認証情報のプルダウンから **「Create new credential」** を選ぶ。
5. **API Key** の欄に、先ほどコピーした OpenRouter の API キーを**ペースト**。
6. Credential モーダルの **Save** を押す。
   > ここでの Save は**認証情報を保存するボタン**で、ワークフローの Save ボタン（廃止済み）とは別物。受講者が混同しやすいので明示的に区別する。
7. 認証が完了すると**緑色の表示**になる。→ 連携 OK。

### 3. 動作確認

1. チャット欄から **`こんにちは`** と送信。
2. → **「こんにちは、ご用件は何でしょうか」**といった返答が返ってくる。「なんちゃって ChatGPT」がひとまず動作する状態になった。
   > 【追記】現行では **Enable Streaming が既定でオン**のため、回答が一文字ずつ流れるように表示される。動画（一括表示）とは見え方が違う。

### 4. ログの確認

- キャンバス下部の **Logs** パネルで、実際の動き（実行履歴）を確認できる。
- 接続した Chat Model で**消費したトークン数**もここで確認できる。どのくらいコストがかかったかを見られる。
- 【追記】Gateway credits を使っている場合は、Cloud 管理画面から**モデル別・ワークフロー別の消費量**を追跡できる。

## 動画中の入力例・設定値（現行版）

| 項目 | 値 |
|---|---|
| API キー名（OpenRouter） | `n8nデモ` |
| Credit limit | **設定する**（例：$5）※動画は未設定 |
| Chat Model ノード | `OpenRouter Chat Model`（またはルートAの Gateway credits 対応モデル） |
| チャット入力 | `こんにちは` |
| ワークフローの保存操作 | 不要（自動保存） |

## 講師が強調すべき点（現行版）

- API キーは**絶対に他人に教えない**。**ノードのパラメータ欄に直書きせず、必ず Credential に登録する。**
- **API キーには必ず利用上限を設定する。**（動画からの方針変更）
- コストは**ゼロではない**。トークン課金であり、**日本語は英語よりトークンを食う**。
- OpenRouter は**事前チャージ（デポジット）制**。
- Logs でトークン消費量を確認する習慣。
- **「API キーなしで始める」選択肢（Gateway credits）が現行にはある。** 挫折ポイントを一つ減らせるので、受講者の状況に応じて使い分ける。
