## このパートの位置づけ

AIエージェントの可能性を劇的に広げる**ツール**という概念を学ぶ。Wikipedia ツールを1つ追加 → 続けて Gmail ツールを追加し、**複数ツールを組み合わせた処理（オーケストレーション）**を体験する。最後に、複数ツールを正しい順番で使わせるための**システムメッセージによる制御**へつなげる。

## 説明している内容

### ツールとは

- 一言で言うと **AIエージェントに与える道具**。
- これまでのAIエージェントは **Chat Model と Memory しか持っていなかった**が、ツールを与えることで **AI に「手足」を授ける**ことができる。
- 具体例：Gmail、Google ドライブ、スプレッドシート、Slack、Notion など様々な外部サービス。
- **AI Agent ノードの下にある「Tool」**から追加する。
- 【追記】n8n が連携できるサービスは **2,000 種類以上**。そのうち **AI ツールとして使えるノード**には、ドキュメント上で「This node can be used as an AI tool」と明記されている。

## 画面操作の手順

### 1. Wikipedia ツールを追加する

1. AI Agent ノードの「Tool」の**＋ボタン**を押す。
2. 検索欄で `Wikipedia` を検索し、**Wikipedia ノード**をクリックして追加。
3. チャットで動作確認：**`Wikipediaで織田信長について調べて`** と送信。
4. → AIエージェント自身が Wikipedia ツールを使い、織田信長に関する情報を出力する。
   - ⑤のシステムメッセージ（関西弁）の名残で、**関西弁で返ってくる**。

### 2. Gmail ツールを追加する（＋認証情報の設定）

やること：**Wikipedia で検索した内容を Gmail の下書きに作成する。**

1. ツールの追加ボタンから **Gmail ツール**を追加。
2. 新しく使うツールは **Credential（認証情報）の設定が必要**。**「Create new credential」**から進める。
3. 認証画面の**「Sign in with Google」**ボタンを押す。
4. 連携する Google アカウントを選択。
5. 「許可しますか」の画面で**チェックを入れて許可**する。
6. n8n の画面に戻ると**緑色の表示**が出る。→ 連携 OK。

> 講師コメント：**Gmail の連携認証は非常に楽**（ボタンひとつで完了する）。
>
> 【追記】n8n Cloud では、Google 以外にも Slack・HubSpot・GitHub などで**同じように「ボタンひとつ」で認証できるサービスが増えている**（Managed OAuth、n8n 2.11 以降）。一方、セルフホストの場合は自分で OAuth アプリを登録する必要があり、手順が変わる。

### 3. Gmail ツールの設定（下書き作成）

| 設定項目 | 説明 | 動画での選択 |
|---|---|---|
| **Resource** | Gmail に何を扱わせるか。Message（メール本文）／Label（仕分け）／Draft（下書き）／Thread | **Draft** |
| **Operation** | 選択したリソースを何するか。Create（作成）／Delete（削除）／Get（既存の下書きの取得）／Get Many（複数取得） | **Create** |
| **Subject** | 下書き・メールの**件名** | **AI に決めさせる** |
| **Email Type** | HTML か Text か | **Text** |
| **Message** | メール**本文** | **AI に決めさせる** |

#### 【名称の修正】「キラキラボタン」の正体

- 動画で「キラキラ（✨）ボタン」と呼んでいるものの正式名称は **「Let the model define this parameter」**（このパラメータはモデルに決めさせる）。
- 押すと、その項目が式の入力欄に変わり、**`$fromAI()`** という関数が自動で入る。
  - 例：`{{ $fromAI("subject", "メールの件名", "string") }}`
- つまり「AI がいい感じにやってくれる」の中身は、**「この項目の値は AI エージェントに決めさせる」という明示的な指定**である、という理解をさせる。
- 解除したいときは、入力欄の **×** を押すと自分で値を入れるモードに戻る。
- 引数を編集すれば、**AI に渡す説明文（何を入れるべき項目か）を自分で書ける**。ここを丁寧に書くほど精度が上がる。

### 4. 動作確認

1. チャットで **`Wikipediaで織田信長について調べ、Gmailで下書き作成。`** と指示。
2. 処理が完了したら、連携した Gmail の画面を確認。
3. → **「織田信長についての調査結果」**という下書きがきちんと作成されている。→ 連携完了。

## オーケストレーション（このパートの締め）

- 複数のツールをつなぎ合わせることで、AIエージェントの可能性をさらに広げられる。
- **しかし問題がある**：複数のツールがあると、**AIエージェントがユーザーの理想とする使い方（順番）どおりに動かないことがある**。
  - 今回で言えば「**Wikipedia を使ったら Gmail で下書きを作成する**」という順番は守ってほしい。
- **そこで重要になるのが、⑤で学んだシステムメッセージ。**
  - 例：「ユーザーの入力情報についてまず Wikipedia で調べて、調べた内容を要約して Gmail の下書きで作成してほしい」と明記する。
- **複数ツールを扱ううえでは、システムメッセージでAIエージェント自身の動きを制御することが非常に重要なポイント**であり、今後も必ず必要になる設定。

### 【追記】制御のもう一つの手段：ツール実行前の人間承認（Human-in-the-loop）

n8n 2.6 以降、**AI エージェントが特定のツールを呼ぶ前に、人間の承認を必須にできる**ようになった。

- 使いどころ：**メール送信・データの削除・外部への投稿など、間違えると取り返しがつかない操作**。
- 今回の題材なら「Gmail の**下書き作成**は自動でよいが、**送信**は必ず人間が承認する」といった設計ができる。
- システムメッセージで「気をつけてね」と頼むのとは違い、**仕組みとして止められる**点が本質的に異なる。
- 講座での扱い：ここでは**概念の紹介にとどめ、実装は受講者の自作段階（⑨以降）で必要に応じて使う**ようにガイドするとよい。

### 【追記】ツールを大量に増やす手段：MCP servers

n8n 2.22 以降、**MCP サーバーをワンクリックで AI エージェントに接続**できるようになった（Notion、Linear、monday.com、Apify、PostHog など）。個別のノードを一つずつ足さなくても、そのサービスの操作一式をツールとして渡せる。

ただし**ツールが増えるほどエージェントは迷う**ため、このパートの結論（＝システムメッセージによる制御が重要）はむしろ強まる。⑧のサブエージェントの動機づけにもつながる。
