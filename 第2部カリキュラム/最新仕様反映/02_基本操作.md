## このパートの位置づけ

n8n の基本操作を覚えながらAIエージェントの基本的な仕組みを理解し、自分のアイデアを形にするための考え方を身につける導入パート。アカウント作成 → Overview ページの機能紹介 → キャンバス画面の基本操作、までを扱う。

**動画版からの構成変更**：動画では最後に「Save の重要性」を置いていたが、現行版では代わりに「**自動保存と Publish の関係**」を置く。ここは受講者が最初につまずくポイントなので、時間を割いて説明する。

## 画面操作の手順

### 1. アカウントの作成

1. 「n8n」で検索し、n8n 公式ホームページを開く。
2. 画面右上の**「Get started」**をクリック。
3. 名前・メールアドレス・パスワードを入力して登録する。
4. 作成が完了すると **Overview ページ**が表示される。

> 補足：n8n Cloud には **14日間の無料トライアル**があり、**クレジットカードの登録は不要**。トライアル中は Pro プラン相当の機能が使え、**実行 1,000 回**までという上限がある。トライアル終了後にアップグレードしないとワークスペースは削除されるが、**90日間はワークフローをダウンロードできる**。

### 1-2.【新規追加】n8n のアカウントは「インスタンス単位」— 他サービスとの違い

受講者が最初につまずきやすいが、動画では触れられていない重要な前提。

**n8n Cloud では、アカウントとインスタンス（ワークスペース）が実質1対1。** サインアップすると、固有の URL を持つインスタンスが1つ生まれ、ログイン情報はその中に属する。Notion や Google のような「1つのアカウントで複数のワークスペースを切り替える」構造ではない。**Slack に近い、インスタンス単位の閉じた世界**と説明すると伝わりやすい。

| | 一般的なサービス（Notion・Google など） | **n8n Cloud** |
|---|---|---|
| アカウントとワークスペース | 1アカウントで複数ワークスペースを切り替え | **実質1対1。サインアップ＝インスタンス作成** |
| 他人の環境への参加 | 自分のアカウントのまま参加 | **その インスタンスに招待され、そこのユーザーになる** |
| チームの分け方 | ワークスペースを分ける | **同一インスタンス内の「プロジェクト」で分ける** |

押さえるべき点：

- **ユーザーはインスタンスに属する。** 各ユーザーは1つの**インスタンスロール**（**Owner** / **Admin** / **Member**）を持ち、権限はそのインスタンスの中で完結する。
  - Admin ロールは n8n Cloud の Pro・Enterprise、セルフホストの Enterprise のみ。
  - **Cloud 管理画面（Admin Dashboard）にアクセスできるのは Owner だけ**（課金・バージョン更新・タイムゾーン・Gateway credits の有効化はここ）。
- **オーナーのメールアドレスはインスタンスごとに一意。** 1つのインスタンスが持てるオーナーメールは1つだけ。
- **インスタンス名（URL）は後から変更できない。** 変えたい場合は**新しいアカウントを作り、ワークフローをエクスポート／インポートで移す**必要がある、と公式ドキュメントが案内している。
- **Credential・ワークフロー・実行履歴・Data tables・Gateway credits の残高は、すべてインスタンス単位。**
  - → ⑧で「一度登録した Credential が別のワークフローでも選べる」のは、**同じインスタンスの中だから**。この伏線をここで張っておく。
- **トライアルが終了するとワークスペースごと削除される。** ワークフローのダウンロード猶予は**90日間**。

> **受講者に必ず伝えること**：**講座で作ったものは、会社の n8n には自動では引き継がれない。**
> 会社の n8n に参加するときは、**別インスタンスの Member として招待される**形になる。持ち込みたいワークフローは、⑨で扱う**エクスポート／インポート**で移す（複数のワークフローや依存関係ごと移すなら `.n8np` パッケージ）。認証情報は移らないので、移行先で登録し直す。

> 【未確認】Starter / Pro プランで**1アカウントが複数インスタンスを持てるか**は、公式ドキュメントに明示がない。インスタンス名の変更に新規アカウント作成を求めている記述から実質1対1と読めるが、断定はできない。受講者から質問が出うる点なので、必要なら事前に確認しておく。

### 2. Overview ページ（旧：ダッシュボード）の主要機能

**画面の構成（2026-09-22 実機確認）**

- **左サイドバー**：`Overview` / `Templates` / `Insights`
- **Overview ページの中のタブ**：`Workflows` / `Credentials` / `Executions` / `Data tables`

| メニュー | 場所 | 説明 |
|---|---|---|
| **Workflows** | Overview 内タブ | 自分が作成していく自動化の仕組み（＝ワークフロー）が一覧表示される。作成中・過去作成分を一元管理する画面。**公開済みのワークフローにはカードに「Published」のバッジが付く** |
| **Credentials** | Overview 内タブ | 外部サービスと連携する際に必要な**認証情報**を管理する画面。Googleスプレッドシート、Googleカレンダー、Gmail、Slack、OpenAI などとの連携に必要。詳細は④で扱う |
| **Executions** | Overview 内タブ | 作成したワークフローが**いつ・どのように動いたか**の履歴（ログ）が一覧記録される画面。赤＝エラー、緑＝Success。**どのバージョンで実行されたかでも絞り込めるようになった** |
| **Data tables** | Overview 内タブ | n8n 上にデータを保存できる、Excel／スプレッドシートのような機能。**ベータではなく正式機能**（1.113 以降、全プランで利用可） |
| **Templates** | サイドバー | 世界中の n8n ユーザーが作成したワークフローのテンプレート一覧。クリックすると n8n の公式テンプレートサイトが開く |
| **Insights**【追記】 | サイドバー | 本番実行数・失敗数・失敗率・**Time saved（自動化で削減できた時間の推定）**・平均実行時間を見られる分析画面 |

> **注意**：この置き場所（サイドバー／Overview 内タブ）と並び順は**バージョンとプランによって変わる。** 上記は 2026-09-22 時点・無料トライアルの実画面。収録時は当日の画面と突き合わせること。

#### Data Tables の説明（現行仕様）

- 本来はデータを扱う際、外部のデータベース（スプレッドシートや Excel）との連携が必要になる。
- **簡単なデータであれば n8n の中で保存・管理できる**のが Data tables。
- **もうベータ版ではない。** 操作経路は3つある：
  1. **Data Table ノード**（ワークフローの中から行の作成・取得・更新・削除・upsert）
  2. **Data tables タブ**（画面から直接テーブルとデータを作成・編集）
  3. **n8n API の DataTable エンドポイント**

#### Templates の説明（現行の数値）

- 現在 **12,428 件**（2026-09-21 時点）のテンプレートが公開されており、日々増え続けている。
- 実際のワークフロー画面とワークフローの説明が記載されている。
- 自分でワークフローを作成する際に、**既存テンプレートからアイデアを持ってくる／自分が作りたいものに近いものを参考にする**という使い方を推奨。⑨のワークショップでも活用する。
- 【注意】**古いテンプレートには 1.x 時代のノード設定が残っているものがある。** インポートして動かない場合は、ノードのバージョン差が原因のことが多い。

### 3. 最初のワークフローを作る（キャンバス画面）

1. サイドバー左上の**作成ボタン**、または Overview ページ右上の**「Create Workflow」**から新規作成する。
2. **キャンバス画面**が開く。この画面上で実際のワークフローを作成していく。
3. 画面左上のワークフロー名をクリックすると、任意の名前に変更できる。
   - 例：`My Workflow 92` → `デモ`
4. **保存操作は不要。** 名前を変えた時点で自動保存される。

### 4. 【全面差し替え】保存と公開 — n8n 2.x の最重要概念

動画では「Save ボタンを押す癖をつける」が最重要ポイントだったが、**現行の n8n には Save ボタンがない**。代わりに、次の2段構えを理解させる。

#### ① 保存は自動（オートセーブ）

- 編集すると **1〜5 秒で自動的に保存される**。ヘッダーに保存中のアニメーションが出る。
- **Save ボタン・コマンドバーの save・保存のキーボードショートカットは、n8n 2.4 で削除された。**
- 自動保存された内容はすべて**ドラフト（下書き）**として保存される。本番には影響しない。
- 通信が切れている間はオートセーブが自動的に一時停止し、復帰すると再開する。保存に失敗した場合はリトライされる。
- （セルフホストのみ）環境変数 `N8N_WORKFLOWS_AUTOSAVE_DISABLED` でオートセーブを無効化でき、その場合は Save ボタンと Ctrl+S が復活する。**n8n Cloud では無効化できない。**

#### ② 本番反映は Publish

- 画面右上の **Publish** ボタン（ショートカット `Shift` + `P`）を押すと、その時点のバージョンが**本番用として公開**される。
- 公開すると初めて、以下が有効になる：
  - Webhook・フォームトリガーが**本番用 URL** を使う
  - スケジュールが設定した時刻に動く
  - 連携アプリからのイベントでワークフローが起動する
- **本番実行は、常に「公開したバージョン」で動く。** 公開後にキャンバスをいじっても、再度 Publish するまで本番の動きは変わらない。
- Publish ボタンの状態表示：

  | 表示 | 意味 |
  |---|---|
  | グレーアウト（無効） | 未公開の変更がない |
  | 有効 | 公開できる変更がある |
  | Published, up to date | 公開済みで、その後の変更なし |
  | Published, has changes | 公開済みだが、その後の変更がまだ本番に出ていない |
  | Published, invalid changes | 公開が必要なトリガーがなく、再公開できない状態 |
  | Published, error | 直近の変更にエラーがあり、直さないと公開できない |

- 公開を取り消す（本番から外す）には、Publish ボタン横のドロップダウンから **Unpublish**（`Cmd/Ctrl` + `U`）。ワークフロー一覧やバージョン履歴からも可能。

#### ③ バージョン履歴

- ヘッダーの**履歴アイコン**からバージョン履歴を開ける。
- できること：**過去バージョンの復元／別バージョンの公開／Unpublish／バージョンへの命名**。
- 復元しても本番実行には影響しないので、安心して過去の状態に戻して試せる。
- **バージョンへの命名は n8n Cloud の Pro / Enterprise プラン、セルフホストの Business / Enterprise プランのみ。** 名前を付けたバージョンは自動削除（プルーニング）の対象外になる。
- **`Cmd/Ctrl` + `S` は「保存」ではなく「Name version（バージョンに名前を付ける）」に割り当てられている。** 1.x の癖で押してしまう受講者がいるので注意喚起する。

#### ④ テスト実行と本番実行の違い（受講者がいちばん混乱する点）

| | テスト実行 | 本番実行 |
|---|---|---|
| 実行方法 | キャンバスの **Execute Workflow** ボタン、またはチャット欄から | トリガー条件の成立（Webhook・スケジュール等） |
| 使われるバージョン | **編集中のドラフト** | **最後に公開したバージョン** |
| Publish の要否 | **不要** | **必須** |

→ **この講座で作る「なんちゃって ChatGPT」は、キャンバスのチャット欄からのテスト実行で完結するため、⑧まで Publish は必須ではない。** ただし⑧でサブエージェントを作る際は例外があるので注意（⑧参照）。

### 5. 【追記】AI による作成支援（現行 n8n の新機能）

動画収録後に追加された機能で、受講者が自力でワークフローを作る段階（⑨）で大きく効く。ここで存在だけ紹介しておく。

| 機能 | できること |
|---|---|
| **AI Workflow Builder** | 「毎朝ニュースを要約して Slack に送りたい」のような**自然言語の指示から、動くワークフローを生成**する。既存ワークフローの修正・デバッグにも使える |
| **n8n Assistant** | チャットからワークフローの作成・編集・テスト・トラブルシューティングを行う |
| **Ask n8n AI** | n8n の使い方について質問できるアシスタント |

## 講師が強調すべき点（現行版）

- ~~n8n には自動保存機能がない。変更のたびに Save を押す~~ → **n8n は自動保存される。押すべきボタンは Save ではなく Publish。**
- **「編集はドラフト、本番は公開バージョン」** の2段構えを最初に頭に入れる。これが分かっていないと、⑧のサブエージェントと、受講後の本番運用でつまずく。
- Workflows / Credentials / Executions / Data tables / Templates の5つは覚えておくこと（＋ Insights）。
- Executions は「ちゃんと動いているか」「エラーならどこで・いつ・どんなエラーか」を確認する重要機能。
- **ネット上の解説の多くは 1.x 時代のもの。**「Save を押す」「Active トグルをオンにする」という説明が出てきたら、現行では「自動保存」「Publish」に読み替える。
