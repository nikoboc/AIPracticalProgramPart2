## このパートの位置づけ

④で会話できるようになったAIエージェントの欠点（記憶がない）を実演で体験させ、**Memory** を追加する。続いて、AIエージェント開発で最重要と位置づける**システムメッセージ**を扱う。

## 前半：メモリ

### 欠点の実演

1. チャットに **`私の名前は田中です。`** と送信 → **「田中さん、こんにちは」**と返ってくる。
2. 続けて **`私の名前は何ですか？`** と質問 → **「ごめんなさい、名前についての情報を持っていません」**と返る。

→ **直前の会話すら覚えていない。** AIエージェントにまだ「記憶」の機能がないため。

> 講師の補足：ChatGPT は過去の会話の記録を踏まえて回答してくれる／覚えてくれる機能を備えているが、このAIエージェントにはまだない。

### 画面操作の手順（Memory の追加）

1. **AI Agent ノードの下にぶら下がっている「Memory」の＋ボタン**を押す。
2. メモリは任意のものを指定できるが、今回は **`Simple Memory`** を選択。
3. 設定画面の項目：

   | パラメータ | 説明 | 既定値 |
   |---|---|---|
   | **Session Key** | この会話をどのキーで識別するか。**どこまでを「同じ会話」とみなすか**を決める。Chat Trigger と組み合わせる場合は既定のままでよい | 自動 |
   | **Context Window Length** | **直近いくつの「やり取り」を記憶として渡すか** | **5** |

4. 動画ではデフォルトの **5 のまま**進行し、キャンバス画面に戻る。

> 【重要な補足】**Context Window Length は「メッセージ数」ではなく「やり取り（往復）の数」。** 5 なら「ユーザー発言 5 件＋AI 応答 5 件＝計 10 件」が毎回 LLM に送られる。
>
> - 値を大きくするほど**会話は自然になるが、毎回の送信トークンが増え、コストと応答時間が増える**（④のコストの話と直結）。
> - 短いタスク特化のエージェントなら 3 まで下げてよい。
> - 長い雑談を想定するチャットボットなら 50 程度まで上げることもある。
>
> 【補足】Simple Memory は **queue モードで動かしている n8n インスタンスでは使えない**（毎回同じワーカーに割り当てられる保証がないため）。n8n Cloud の通常利用では問題にならないが、自社のセルフホスト環境に持ち込む受講者には伝えておくとよい。

### 動作確認

1. 再度 **`私の名前は田中です。`** を送信 → 同様の返答。ただし **Memory のところにチェックがつき、実行されたことが確認できる**。
2. **`私の名前は何ですか？`** → **「あなたの名前は田中さんです。よろしくお願いします」**と返る。→ 記憶機能が追加できた。

### 押さえるポイント

- 作成するワークフローの目的に応じて、
  - そもそも**記憶機能をつけるのか／つけないのか**
  - つけるなら**どれくらい会話を記憶させたいのか**（＝**どれだけコストをかけるか**）

  を設定する必要がある。

## 後半：システムメッセージ

### システムメッセージとは

- **AIに与える行動指針・役割設定**のこと。
- AIエージェントがユーザーと会話する際に、**どういった役割で／どういった立場で回答したらいいか**という「マニュアルのようなもの」を設定できる。
- 講師の位置づけ：**メモリ機能よりももっと強力で、さらに重要な機能。AIエージェント開発において最も重要と言っても過言ではない。**
- 【追記】n8n の公式な説明は「会話が始まる前にエージェントに送るメッセージ。エージェントの意思決定を導くもの」。**既定値は `You are a helpful assistant.`**

### 画面操作の手順

1. **AI Agent ノード**を開く。
2. 下部の**「Add Option」**を選択 → **「System Message」**を選ぶ。
3. システムメッセージの入力欄が追加される。
4. 例：**`関西弁で回答してください`** と入力。
5. パネルを閉じて実行する（**保存操作は不要**）。

> 【注意】**System Message は既定で隠れている。** 「Add Option」を押さないと出てこないため、設定し忘れる受講者が多い。n8n を使っていてエージェントの精度が出ない場合、ここが空のままというケースが非常に多い。

### 動作確認

- 質問すると**コテコテの関西弁**で回答が返ってくる。
- それまでの回答と**口調が明確に変わった**ことを確認する。

### 押さえるポイント

- システムメッセージを使うと、**応答のスタイルだけでなく、指示の処理方法まで AI をコントロール・制御できる**。
- 重要な理由：**今後さまざまなツールをAIエージェントに追加していくにあたり、システムメッセージが「与えられたツールの使い方」を制御するために必要不可欠**になるから（⑥・⑧で実感する）。

### 【修正】英語で書くほうが精度が高い、という話について

- 動画では「**AIは英語の指示のほうが精度の高い回答を出してくれる**（LLM にとって日本語より英語の情報のほうが多いため）」と断定的に説明している。
- **現行の主要モデルでは、日本語の指示でも十分に高い精度が出る。** 動画収録時よりモデルの日本語性能は明確に向上している。
- 現行版での言い方の目安：
  - **まずは日本語で書いてよい。** 日本語で書いたほうが、自分の意図を正確に書き切れる。
  - **精度が出ない・指示が守られないときは、英語で書き直して比べてみる**という使い分けを教える。
  - 長く複雑なシステムメッセージでは、英語のほうが安定することがまだある。
- 【追記】モデルによって指示の効き方が違うため、**システムメッセージの善し悪しは「モデルを変えて比べる」ことでも検証できる**。⑨の「反復」と結びつく。

### 【追記】現行 AI Agent ノードのその他のオプション

動画には出てこないが、講座後半（⑥⑧）や受講者の自作で効いてくるもの。

| オプション | 説明 | 既定 |
|---|---|---|
| **Max Iterations** | エージェントが答えを出すまでにモデルを実行する最大回数。ツールを何度も呼ぶエージェントで上限に当たることがある | 10 |
| **Enable Streaming** | 回答をリアルタイムに流して表示する | オン |
| **Return Intermediate Steps** | エージェントが途中でどのツールをどう使ったかを出力に含める。**デバッグに有用** | オフ |
| **Force Tool Call on First Iteration** | 最初の応答で必ずツールを呼ばせる。小さめのモデルが「ツールを使わず文章で答えてしまう」問題への対策（n8n 2.40 で追加） | オフ |
| **Enable Fallback Model** | 主モデルが失敗・利用不可のときに使う予備のモデルを接続できる | オフ |

## 動画中の入力例・設定値（現行版）

| 項目 | 値 |
|---|---|
| Memory ノード | `Simple Memory` |
| Context Window Length | `5`（デフォルトのまま） |
| System Message | `関西弁で回答してください` |
| チャット入力 | `私の名前は田中です。` / `私の名前は何ですか？` |

## 講師が強調している点（現行版）

- メモリがない状態を**先に体験させてから**追加する構成になっている。
- **Context Window Length は「往復の数」であり、コストに直結する設定。**
- システムメッセージは AIエージェント開発の最重要機能。**Add Option の中に隠れているので、必ず開いて設定する。**
- ~~複雑な指示は英語で書く~~ → **まず日本語で書き、精度が出ないときに英語も試す。**
